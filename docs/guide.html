Beta.3 · public source preview 1

Experimental Linux CPU software for volunteer testers. This exact public source package has passed its native build, 1,031-input/four-implementation hash and full-scratchpad qualification, self-test, 124 production tests, 15 tuning-tool tests and actual 192-worker huge-page qualification on one 7995WX desktop.

The public build reproduced the benchmarked native binary. The matched native comparison measured 111.168 kH/s for beta.3 versus 110.234 kH/s for beta.2, with the same GCC 14 and CPU settings. A separate 300-second pool check finished normally with 38 accepted USER shares and a 110.870 kH/s local session average. Long soak, a full real beta.3 fee cycle, deliberate reconnect exercise and a matched 5% lead over BzMiner remain unverified. See current validation and the sanitized evidence.

What it does

OverXelis performs XelisHashV3 CPU work and connects to a compatible XELIS Stratum pool. You supply your own public payout address, worker name, and pool. You keep control of your wallet. No seed phrase, private key, exchange login, deposit, browser miner, or account registration is needed by this program.

The source includes a disclosed 1% scheduled developer mining-time allocation. It starts with 5,940 seconds (99 minutes) of active user work, then allows a fee window of up to 60 seconds, including connection setup. USER and FEE use separate connections and worker names. The developer destination is:

  • Pool: stratum+tcp://xel-us.kryptex.network:7019
  • Public payout address: xel:pqu4e39zln0g7lx9grdhj3tavuy6e45sjglp9ss9n6lx2zc0w9fqqxhxxvt

The user's password is not reused for the developer login. Already-mined user shares are not relabelled as developer shares. Paused/offline user time does not count toward the next fee window. Failed fee connections are skipped, without accumulated debt or catch-up. Restart resets this beta's schedule; short sessions can contribute less than 1%. Scheduler timing is not hard real-time and is logged. Share discovery is random, so 1% time does not mean exactly 1% of coins. Pool fees, network charges, energy costs, and brief connection handovers are separate. The fee is not a wallet withdrawal.

Requirements and scope

Linux x86-64, an AES-NI-capable CPU, Python 3.10+, GCC 14 with GNU binutils, and an Internet connection to your chosen XELIS pool. Build on the computer that will mine: the library is optimized for that CPU and should not be moved to a different instruction set. No Windows, macOS, ARM, GPU or automatic service installation is supplied.

Run as a normal user. The public program refuses root. Use ordinary memory for a first test. hugetlb is an explicit choice for users with huge pages and permissions already configured; requested huge-page memory never silently falls back. The miner does not change clocks, power limits, GPU settings, services or kernel memory settings.

Arrange Python, GCC 14 and GNU binutils through a trusted operating-system or private toolchain setup first. The archive includes no installer and fetches no compiler, executable or external code. Stop existing CPU mining normally before building, qualifying or running. The measured 7995WX profile used 192 threads and huge pages with the competing CPU miner stopped; other hardware and shared workloads need their own measurements.

Download and verify

Open the beta.3 GitHub prerelease and select the named OverXelis-Miner-1.0.0-beta.3-public-source-preview.1.tar.gz and SHA256SUMS-beta.3-public-source-preview.1.txt under Assets. The website download section also provides exact mirrors. GitHub’s automatically generated repository ZIP is a different archive.

The named archive contains 308,170 bytes. Its SHA-256 is a53075dd73977796281780767ff4387c8c788a951630a468b5591fd6731cee12. Obtain its matching checksum file, then verify before extracting into a fresh folder. A checksum detects unexpected changes; it is not a publisher signature.

sha256sum --check SHA256SUMS-beta.3-public-source-preview.1.txt && \
tar -xzf OverXelis-Miner-1.0.0-beta.3-public-source-preview.1.tar.gz && \
cd OverXelis-Miner-1.0.0-beta.3-public-source-preview.1

These commands proceed only when the preceding check succeeds. Stop on any failure. The tarball contains source and saved public test vectors, without a precompiled workstation binary or private configuration. Earlier beta.2 archives and tags remain unchanged in release history.

Build and check the hash engine

Use an already installed GCC 14 executable. Replace /absolute/path/to/gcc14 below with its actual absolute path. This is the tested ordinary non-PGO build; PGO remains experimental. GCC 11’s development build was slower on the target and is not the recommended compiler for beta.3.

python3 -I -B build_public.py --compiler /absolute/path/to/gcc14 && \
python3 -I -B qualify_public.py && \
bash run.sh --self-test

The build checks required exports and rejects unresolved native symbols. The qualifier checks 1,031 inputs through four C implementations, compares full scratchpad contents and replays saved answers from the independent Rust reference. It does not newly execute Rust. Any failure blocks mining. Preserve build/ and evidence/ logs; use a fresh extracted copy when rebuilding.

Check actual huge-page workers

After full kernel qualification passes, users with huge pages already available can verify the actual worker scratchpads before benchmarking. Change the thread count to match your intended setup:

python3 -I -B tools/qualify_worker_layout.py --threads 192 \
  --output evidence/worker-layout-192.json

This offline check requires huge pages for every worker and verifies one terminal-nonce hash per worker against the C reference. It makes no pool connection. A worker correctness check does not itself select the fastest thread count.

Add your wallet, pool, and worker

The wizard writes a private local configuration file, but does not start mining:

bash run.sh --configure

Enter your mainnet xel: payout address. This is not your seed phrase. Enter a compatible pool URL, such as Kryptex's North America TCP endpoint:

stratum+tcp://xel-us.kryptex.network:7019

The endpoint is a suggested default, not a requirement. Only the fee destination is fixed by this preview. Other pool compatibility is not guaranteed. Supported URL forms are stratum+tcp://host:port, stratum+ssl://host:port, and stratum+tls://host:port; use the port published by the pool. TLS connections verify the certificate and hostname. TCP traffic is unencrypted. Do not place passwords inside a pool URL or use your exchange-account password as a worker password. The usual pool worker password is x, unless the pool specifies another.

Choose a unique worker label, a thread count your computer supports, and ordinary or hugetlb. The wizard's default thread count uses discovered physical cores first; you may choose a different number. Too many threads can make the computer unresponsive and does not guarantee more hashrate.

Review the file and check it without hashing or connecting:

bash run.sh --check

The payout check is basic syntax validation, not a cryptographic address-checksum or ownership proof. Double-check the address; the pool must accept it. There is no default user payout address. The distributed example deliberately contains an invalid placeholder so it cannot silently mine to the developer as USER.

Optional 7995WX profile and CPU order

config.7995wx.example.json requests 192 threads, hugetlb and cpus: null for automatic physical-first selection. It is an optional profile for already configured huge pages, not a universal fastest setting. The generic example remains eight threads with ordinary memory.

Both examples contain an invalid public payout placeholder. For a fresh private config.json, choose an example, enter your own public payout address, pool and worker, and protect the file with chmod 600 config.json. Preserve an existing configuration rather than overwriting it. Run bash run.sh --check before mining.

For measured placements, beta.3 also accepts an optional cpus JSON array in exact worker order. It must contain one distinct allowed integer CPU identifier per thread. Leave it absent or null for automatic selection. The check command prints the chosen order before native hashing or networking starts. The browser helper and terminal wizard retain automatic selection.

Start and stop

bash run.sh --config config.json --accept-dev-fee

Keep the terminal open. Press Ctrl+C to stop. To run a finite initial test:

bash run.sh --config config.json --accept-dev-fee --duration 900

A short test does not validate the fee transition. The first fee window follows 99 active user-mining minutes. Keep a session running through an observed DEV FEE START → DEV FEE END → resumed USER work before claiming fee-cycle success. A fee window can find no share by chance; that alone is not failure.

Look for authorization, accepted USER shares, the intended worker count, and no invalid-local results. The console separates USER and FEE shares, reports local completed-hash rate, and logs elapsed active time. Its local/session rate includes both roles and is gross throughput, not net user payout. Pool-side rates depend on accepted shares and may vary in short samples.

Troubleshooting

  • Missing files / checksum mismatch: stop and obtain a fresh matching release. Do not bypass the integrity check or mix source editions.
  • Build or hash qualification fails: preserve logs, compiler version and CPU model. Do not mine with the failed binary.
  • Another miner detected: stop that CPU miner using its own normal procedure. OverXelis never kills it or disables its service.
  • Huge pages unavailable: use ordinary for the initial test, or configure huge pages yourself using trusted instructions. The program refuses silent fallback when hugetlb was requested.
  • Authorization fails: check your public address, pool, worker and worker password. This is not a reason to send a private key to anyone.
  • Paused connection: this source preview reconnects after 30 continuously paused seconds without usable work. An active miner is not reconnected solely because no share was found.
  • Low rate: record a sustained sample after warmup. Compare equal thread, memory, power, thermal and workload settings. Startup peaks are not a benchmark.
  • Long sessions: native workers now use bounded tracking of per-worker nonce progress, preserving duplicate protection across jobs, reconnects and USER/FEE transitions. The old 32,768-entry stop no longer applies to production native streams. The legacy exact-input limit remains for injected test engines without that native stream contract; long-soak reliability still needs testing.
  • Security software warning: do not disable protections blindly. Review the source, checksum, release identity and the warning before deciding to proceed.

Feedback

Use the project's GitHub issue forms for bugs or benchmark results. Provide the version and packaging edition, Linux distribution, CPU model, compiler, threads, memory mode, duration, local average, accepted/rejected counts, reconnects, and a short redacted log. State whether a full fee cycle completed. For a speed comparison, name the other miner/version and match settings. Do not post seed phrases, private keys, passwords, API tokens, IP addresses, full payout addresses, or unredacted configuration files. Public issues are visible to everyone.

Evidence and limitations

The beta.3 validation record and sanitized evidence JSON describe the exact public archive, compiler/native identity, 124 + 15 tests, full hash/scratchpad qualification, 192-worker layout, matched four-pair native benchmark and finite pool run. The immutable archive’s README and VALIDATION.json record preparation-time requirements; the dated external report adds completed execution evidence without changing the archive.

The 111.168 kH/s benchmark value is the weighted result of four separate 60-second candidate samples, not a continuous four-minute run. The 110.870 kH/s pool-session display is local completed-hash throughput, including startup and job waits; it is not a pool-side estimate or net payout rate. These tests exceeded the 110.615 kH/s development target on this desktop. Other environments, long soak, a full real beta.3 fee cycle, deliberate reconnect exercise and a matched 5% lead over BzMiner remain unverified.
