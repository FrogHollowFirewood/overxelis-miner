01 / The approach

Know what your
miner is doing.

Clear settings, visible fees, and correctness checks before hashing. No promises of guaranteed returns or a universal speed advantage.

01

Choose your destination

Enter your own XELIS payout address, compatible Stratum pool, and worker name. No wallet seed, custody, or deposit.

02

See both sides of the fee

Separate USER and FEE modes show where work is going. The terminal reports accepted shares and active-time accounting.

Run the public preview in the foreground and stop with Ctrl+C. It does not install an autostart service or change your clocks.

04 / Get started

From source to
your first share.

Download and verify first. Follow the complete guide for dependencies, build checks, memory modes, and troubleshooting.

01

Verify, then extract

Download the archive and its checksum file. Stop if the checksum fails. A checksum is not a publisher signature.

sha256sum --check SHA256SUMS-beta.4-public-source-preview.1.txt && \
tar -xzf OverXelis-Miner-1.0.0-beta.4-public-source-preview.1.tar.gz && \
cd OverXelis-Miner-1.0.0-beta.4-public-source-preview.1
02

Build and qualify

Stop other CPU miners normally. Replace /absolute/path/to/gcc with your installed GCC executable; see the tested compiler contexts in the guide. The miner fetches no compiler. Do not bypass a failed hash check.

python3 -I -B build_public.py --compiler /absolute/path/to/gcc && \
python3 -I -B qualify_public.py && \
bash run.sh --self-test
03

Add your settings

The terminal wizard asks for your public payout address, pool, worker name, threads, and memory mode. No private keys.

bash run.sh --configure && \
bash run.sh --check
04

Start deliberately. Stop anytime.

The flag acknowledges the disclosed 1% scheduled developer fee. Keep the terminal open. Ctrl+C stops this miner.

bash run.sh --config config.json --accept-dev-fee

New to source builds? Start with the complete installation guide, not a copied command alone.

07 / What to expect

Honest answers.
Useful testing.

Is OverXelis officially part of XELIS?

No. OverXelis Miner (OXM) is an independent community project. It is not affiliated with or endorsed by the XELIS project, Slixe, or Kryptex. XELIS is the network this software mines.

With gratitude: thank you to Slixe (GitHub profile, opens in a new tab) for creating XELIS and for his development work, and to the wider XELIS contributor community. We deeply value the project’s work on privacy, open participation, and programmable digital money. This acknowledgment expresses our appreciation—not an endorsement of OXM.

What do our recorded tests show?

The beta.4 desktop hour in the panel above used a 7995WX, 192 threads, hugetlb and GCC 15.2 non-PGO, with GPU mining paused and Mining100 selected for all six controlled fans. Across over 61 active USER minutes after settling, 366 rounded Local displays averaged 121.16 kH/s and the lowest was 120.908 kH/s. Kryptex accepted 393 USER shares during measurement, with zero rejected or unresolved. This is a local display mean, not a raw whole-hour count, pool-side rate or GPU-on guarantee.

Short desktop 24/32-thread counter measurements and three physical rigs’ startup checks are reported separately. Read the current validation record. The matched beta.3/beta.2 benchmark and earlier six-miner observations remain historical; no matched beta.4 BzMiner advantage is established.

Can I use Windows, a GPU, or an ARM computer?

This download is a Linux x86-64 CPU source preview only. It does not include a Windows executable, a macOS build, an ARM build, or a GPU miner. Do not assume compatibility with untested environments.

Will opening this page use my CPU to mine?

No. This is a static project website. Mining begins only when you deliberately run the installed miner on your own computer. There is no browser miner, remote activation, or automatic service installation.

What still needs validation?

A full real beta.4 USER → FEE → USER cycle, repeated fee cycles, deliberate reconnect exercise, a 24-hour soak, broader CPU/distribution support and a matched BzMiner comparison remain open. The completed beta.4 hour did not reach the first 99-active-minute fee window. Its above-120 result does not qualify GPU mining running at the same time. Older beta.2 fee-cycle evidence remains historical. See the current scope and limits.

Why do local and pool hashrates differ?

The console counts local completed hashes. The pool estimates useful work from submitted shares. Short samples, connection gaps, stale shares, and fee allocation can affect the comparison. Report the measurement window and accepted/rejected counts.

What happens if I see an error or a security warning?

Stop on invalid hashes or checksum errors. Preserve redacted logs. Do not blindly disable security software. Beta.4 native workers retain bounded nonce tracking instead of beta.2’s 32,768-entry cache stop. Duplicate and lower nonce protection persists across jobs, reconnects and USER/FEE changes. This correction does not establish long-soak reliability.
