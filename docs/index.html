02 / Beta.4 hotfix · 6 November 2026

Measured work.
Clear conditions.

The current download is crash-fix preview 2. The new logged hour, earlier short GPU-on counter measurements and older unpatched hour use separate evidence and methods.

Beta.4 crash fix · upgrade to source preview 2. The earlier beta.4 source preview 1 can stop with an integer divide-by-zero fault, shown by the shell as “floating point exception.” Preview 2 checks the selected production kernel before that division, consumes the failed nonce, and excludes it from completed work and share submission. The first failing input is retained in the native runtime for diagnostics; the public launcher does not automatically save it to disk. The cause of the original zero intermediate value remains unverified because that input was not saved. Read the fix, qualification and limits.

New: development hotfix logged hour · 6 November 2026

60 minutes 27.49 seconds after warmup · 192 huge-page workers · 119.739756 kH/s mean of 361 rounded local displays; sampled minimum 119.517, maximum 119.978 kH/s. The measured interval accepted 444 USER shares; the full session accepted 450, with zero rejected or unresolved displayed. All native workers closed normally after a requested stop.

This is logged continuity evidence from the development hotfix, whose native library is byte-identical to the qualified public preview-2 build. The launcher retained its earlier preview-1 banner. Raw hash-counter boundaries and a monotonic interval were not saved; native drops/undefined skips, GPU activity, cooling and temperatures were not recorded for this session. This is not an exact-counter hour, a full fee cycle or a 120 kH/s guarantee.

No invented hash

A zero round modulus is rejected before division. That nonce is consumed, is not counted as completed work, and cannot enter the submission queue.

REAL POOL WORK

25 and 28 accepted shares

Two approximately 191-second measured windows after warmup, with zero rejected, unresolved or queue-dropped work. These are short observations, not a soak test.

CORRECTNESS CHECKS

1,031 inputs · four C paths

Saved Rust answers replayed, complete scratchpads compared, and 192 actual huge-page workers verified. Forced-zero tests exercised 1, 24, 32 and 192 workers.

Scope: zero rejected, unresolved or queue-dropped work was reported in these short measurements. Saved Rust answers were replayed through four C implementations for 1,031 inputs, full scratchpads were compared, and 192 actual huge-page workers were verified. Forced-zero guard tests exercised 1, 24, 32 and 192 workers. Rust was not newly executed. These checks support the observed selected-kernel repair and normal hash behavior; they do not establish long-term stability, broad hardware performance, an exact-counter hotfix hour, a fee-cycle pass or a general 120 kH/s guarantee.

The production selected kernel uses the checked path. Reference and experimental kernels retain their earlier zero-modulus behavior; the legacy void selected API deliberately traps on failure. The hotfix does not define a new consensus hash for an undefined input. Capturing and replaying a naturally failing input remains necessary to distinguish a reference edge case, an optimization discrepancy or a transient computation fault.

01

Verify, then extract

Download the archive and its checksum file. Stop if the checksum fails. A checksum is not a publisher signature.

sha256sum --check SHA256SUMS-beta.4-public-source-preview.2.txt && \
tar -xzf OverXelis-Miner-1.0.0-beta.4-public-source-preview.2.tar.gz && \
cd OverXelis-Miner-1.0.0-beta.4-public-source-preview.2
02

Build and qualify

Stop other CPU miners normally. Replace /absolute/path/to/gcc15 with your installed GCC 15 executable; see the tested compiler contexts in the guide. The miner fetches no compiler. Do not bypass a failed hash check.

python3 -I -B build_public.py --compiler /absolute/path/to/gcc15 && \
python3 -I -B qualify_public.py && \
bash run.sh --self-test
03

Add your settings

The terminal wizard asks for your public payout address, pool, worker name, threads, and memory mode. No private keys.

bash run.sh --configure && \
bash run.sh --check
04

Start deliberately. Stop anytime.

The flag acknowledges the disclosed 1% scheduled developer fee. Keep the terminal open. Ctrl+C stops this miner.

bash run.sh --config config.json --accept-dev-fee

New to source builds? Start with the complete installation guide, not a copied command alone.

07 / What to expect

Honest answers.
Useful testing.

Is OverXelis officially part of XELIS?

No. OverXelis Miner (OXM) is an independent community project. It is not affiliated with or endorsed by the XELIS project, Slixe, or Kryptex. XELIS is the network this software mines.

With gratitude: thank you to Slixe (GitHub profile, opens in a new tab) for creating XELIS and for his development work, and to the wider XELIS contributor community. We deeply value the project’s work on privacy, open participation, and programmable digital money. This acknowledgment expresses our appreciation—not an endorsement of OXM.

What do our recorded tests show?

The hotfix recorded 119.302920 and 118.955001 kH/s from completed-hash counts in two approximately 191-second Kryptex windows after warmup on one 7995WX with 192 huge-page workers and GPU mining running. The windows accepted 25 and 28 USER shares, with zero rejected, unresolved or queue-dropped work. The older 121.16 kH/s hour belongs to the unpatched GPU-paused build and does not qualify the hotfix.

Read the current hotfix validation and preserved historical methods. No universal rate or matched BzMiner advantage is established.

Can I use Windows, a GPU, or an ARM computer?

This download is a Linux x86-64 CPU source preview only. It does not include a Windows executable, a macOS build, an ARM build, or a GPU miner. Do not assume compatibility with untested environments.

Will opening this page use my CPU to mine?

No. This is a static project website. Mining begins only when you deliberately run the installed miner on your own computer. There is no browser miner, remote activation, or automatic service installation.

What still needs validation?

An exact-counter hotfix hour, long soak, full fee cycle, deliberate reconnect exercise, broader compiler/CPU qualification and a matched BzMiner comparison remain open. The historical unpatched hour and old rig startup checks are not hotfix qualification. The origin of the zero intermediate value still needs a captured input and independent replay. See the current scope and limits.

Why do local and pool hashrates differ?

The console counts local completed hashes. The pool estimates useful work from submitted shares. Short samples, connection gaps, stale shares, and fee allocation can affect the comparison. Report the measurement window and accepted/rejected counts.

What happens if I see an error or a security warning?

Stop on invalid hashes or checksum errors. Preserve redacted logs. Do not blindly disable security software. Beta.4 native workers retain bounded nonce tracking instead of beta.2’s 32,768-entry cache stop. Duplicate and lower nonce protection persists across jobs, reconnects and USER/FEE changes. This correction does not establish long-soak reliability.
