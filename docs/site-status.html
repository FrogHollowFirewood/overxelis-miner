Know what is tested.

OverXelis Miner 1.0.0-beta.2 · Public Source Preview 2. This is experimental Linux x86-64 CPU software, not a stable binary release.

Available now

The named Linux source archive, SHA-256 checksum, installation guide, local configuration helper, and public GitHub issue forms. Website downloads do not require signing in.

Still under validation

A complete real USER → FEE → USER cycle, completed 24-hour stability, broader platform compatibility and permissions on other systems remain open. Native build, qualification and initial accepted work on one desktop are now documented below.

Preview 2: attribution corrected, old release preserved

The package notice now distinguishes historical development files from shipped files. kernels/rc1.c is historical and is not included. The notice also identifies the conditional TNN-derived ChaCha path used by the selected kernel, with its license retained. Mining algorithms, pool behavior and the fee policy are unchanged.

At release preparation, 62 offline tests passed from the exact new archive. The native build gate initially refused while another CPU miner was active; no guard was bypassed. After that miner was stopped by its owner, subsequent native and initial live tests succeeded as described below. The full real fee cycle and extended stability remain pending. Post-release native and live-pool checkpoint

29 October 2026 (UTC): the exact Preview 2 download was built as a normal user on an AMD Ryzen Threadripper PRO 7995WX desktop. All 1,031 retained inputs passed across four C implementations, including full scratchpad comparisons and replayed Rust answers. The public CLI self-test also passed; this was not a new Rust execution.

The 180-second ordinary-memory test used 192 workers and ended cleanly with 23 accepted user shares, zero rejected and zero unresolved submissions. Its short session average was 92.462 kH/s; this is functional-test context, not a benchmark or a change to the 110.615 kH/s historical development reference.

The subsequent normal-user huge-page session allocated 192/192 huge-page workers, authorized with Kryptex and submitted accepted user shares. At the dated checkpoint it was running a bounded 86,400-second observation. The 24-hour result and first full real fee cycle are not yet complete. The unchanged fee policy waits for 5,940 active user seconds before a window of up to 60 seconds. This page is not a real-time dashboard.

An external observer records temperature, process state, rates and role transitions, and stops only its own test child on a conservative 85 °C cutoff, monitoring failure, a recognized competing CPU miner or an explicit stop request. It installs no service and does not automatically restart a failed test. Existing GPU mining was preserved. USER and FEE use the same maintainer-controlled wallet with distinct worker roles, so separate-wallet payout outcomes are not established by this test.

Read the post-release validation record. The source archive, fee code and installed miners were not changed. The archive’s VALIDATION.json remains the original packaging-time snapshot; this later record adds evidence without replacing the release.

Known beta limitations

The developer-fee schedule resets after restart. The duplicate-input cache stops the beta at 32,768 entries. Non-root huge-page permissions vary by system. No Windows, macOS, ARM, or GPU package is provided. Preserve logs and do not bypass failed integrity or hash checks.

Report a problem

Use the GitHub bug or benchmark forms and the feedback template. Redact secrets, full payout addresses, and private network details. No private security-reporting channel is verified; obtain one from the owner before sharing sensitive vulnerability details.
